# Claude 本地记录事实核查

核查日期：2026-10-27。文章网页无法读取，以用户贴出的全文为核查对象。结论：部分本地机制属实；“不清理就秒封”没有可复核因果证据；“5%–7% 是封号没收款、基本纯利润”曲解了披露。

## 收入原文的含义

[Anthropic 公告](https://www.anthropic.com/news/s1-sec)确认 2026-10-26 提交 S-1。[SEC 原件](https://www.sec.gov/Archives/edgar/data/2130357/000162828026067168/anthropicpbc-sx1.htm)在收入讨论（印刷页码 145 附近）解释：检测、调查、执行需要时间，因此会在限制或终止客户访问之前，按已提供服务确认收入；估计截至 2026-09-30 的九个月中，来自后来被判定违反使用政策或商业条款的客户的收入占比约 5%–7%。

该口径不是没收未消费余额，也不是全部来自个人订阅或某个国家的用户。文件没有由此得出“纯利润”，已经提供的服务也不能被假定零成本。文中的金额换算即使算术成立，也不能改写统计对象；本核查不为其金额或退款断言背书。

## 四项技术说法

| 文章说法 | 证据 | 判定与边界 |
| --- | --- | --- |
| 账号 UUID 与稳定设备标识 | 当前 CLI 2.1.307 的内嵌代码中，`device_id` 使用读取/生成 `userID` 的函数；该函数优先复用配置中符合格式的值。官方目录文档确认 `.claude.json` 保存账号和应用状态。 | 机制存在。字段并非一定字面叫 `device_id`；本机配置有 `oauthAccount.accountUuid` 和 `userID`，不输出值。客户端可关联这些标识，不等于已证明服务端如何使用它们封号。 |
| `telemetry/1p_failed_events.*.json` 失败重试 | 本机可执行文件包含该前缀、读取失败批次、发送和重试/退避逻辑；也有另一种 stream 存储及迁移分支。 | 失败队列机制存在，但路径并非所有模式的唯一存储。当前匹配文件数为 0，不代表没有遥测。代码中的“失败后重试”本身不能证明会探测代理背后的真实公网地址。 |
| 滚动配置备份 | [官方目录说明](https://code.claude.com/docs/en/claude-directory)说明配置自动备份、保留最近五份，并额外保存无法解析的版本。本机匹配备份文件数为 5。 | 属实；配置副本可能包含账号元数据。本轮没有输出备份正文，也没有证明服务端会扫描这些备份。 |
| Keychain / `.credentials.json` 旧令牌 | [官方认证文档](https://code.claude.com/docs/en/iam)说明 macOS 使用加密 Keychain；Keychain 写入失败可回落到权限为 0600 的文件，其他平台使用凭据文件。 | 凭据来源须统一处理，残留或恢复错误可能造成用错账号。两处不是必然同时存在；本机没有该默认凭据文件，本轮未读取真实 Keychain 令牌。存在旧令牌不等于它仍被采用，更不等于已触发封禁。 |

本机只读检查范围为配置字段是否存在、文件数量与默认文件是否存在；可执行文件 SHA-256：`5b113a7752119470f1da419cb0e608af3361cae25b614216b13022093958fb2a`。静态代码只能证明包含对应逻辑，不能代替实际运行、服务端日志或封禁原因证据。

[官方数据使用说明](https://code.claude.com/docs/en/data-usage)描述运行指标与错误报告，以及相关隐私开关。这些开关不构成“全部安全检测关闭”或免封保证，本轮不修改它们。

## 对本项目的影响

已有源白名单覆盖账号/本地标识、遥测缓存和配置备份，已有原生凭据桥处理默认 Code/Desktop 凭据。应验证的是：分端资料来源准确、切换时不混用旧凭据、目标缺失端不残留上一身份、故障保留可恢复检查点。文章没有提供扩大删除范围、轮换标识或承诺防封的依据。本轮不新增这些行为。

会改变封禁因果判定的证据：服务端明确解释所用信号，或能够控制账号、付款、地区、网络和行为等混杂因素的可复现实验。当前没有这些证据，结论保持“可能具有关联用途，具体封禁因果未证实”。
