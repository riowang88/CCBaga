## 1. 目标与交付边界

用户选择一个本地身份后，三端恢复该身份**已有**的登录资料；缺失端明确提示并引导官方登录，不继续使用上一个身份的活动凭证。浏览器始终复用其绑定目录和既有指纹设置。账号切换不切代理节点。

## 4. 分端状态与官方登录引导

### 4.1 最少状态

| 维度 | 状态与呈现规则 |
| --- | --- |
| 安装/运行 | 未安装、未运行、运行中、无法确认；不因未运行推断没有凭证 |
| 档案内资料 | 有、无、无法读取/旧档案未标注；与当前客户端登录状态分列。B 目录绑定只表示资料已关联，不能称 Cookie 已加密入库 |
| 当前身份 | 匹配、异号/组织不符、待确认；附来源与时间。复用现有 UUID/组织或有界邮箱/组织判读；来源缺失不猜测、不按昵称合并 |
| 登录/权益 | 已验证可用、未登录/需重新登录、尚未验证；权益不足独立列为原因。本机 CLI 最新手工回报为 Pro 已登录；产品常规刷新仍仅显示本地元数据，不是全局禁用 CLI |
| 网络 | 未核验、已核验的指定路由样本、与基线不符、证据已过期；不把当前账号状态和网络状态揉成一个绿灯 |

普通刷新不解密全库、不暴露令牌。历史浏览器档案缺新字段仍可使用；在用户明确保存/关联时才按已有事务更新必要元数据。人工确认只能显示“用户已确认”，不能成为自动匹配的证据来源。

### 4.2 最小登录流程

检查安装与目标档案 → 判断是否已登录/异号 → 打开官方入口 → 用户完成验证 → 核对实际身份/组织 → 在静止条件下将指定端关联到原档案。任何取消、超时、识别失败、保存失败都不报关联成功、不覆盖最后有效代次。

浏览器授权必须先确认当前目标 B 资料，再在该资料打开官方生成的链接；**不先交系统默认浏览器再补救，不改默认浏览器**。CLI 能否受控获得链接并保持回调/PKCE 等官方流程完整，需按本机版本验证；若无法做到，应停在可解释的引导状态，不自动退回默认浏览器、不复制 Cookie/令牌。App 原生登录沿用官方入口，涉及浏览器时同样核对资料。

异号先保护现场并提示，不自动登出/切号。资料归属未知不合并为目标账号；明确关联只补该端，不吸收其他端异号资料。缺失端或权益不足可跳过；不自动购买、升级、改走 API Key。成功打开窗口、页面已登录、官方 auth status 或本地未过期都不替代真实业务成功。

## 5. 联合切换与缺失端

流程固定为：目标校验和进程预检 → 用户保存工作并确认正常退出 → 静止条件下保存当前有效检查点 → 恢复目标受限资料并提交 B 选择 → 解除本软件互斥 → 按用户所选端启动 → 分端显示资料、登录与网络结果。

三端相关进程未退出或存在无法排除的占用时，不替换资料。网络未核验单独报告，不新增全局切换禁令。正常退出超时返回具体阻塞对象，不新增无提示强杀，不结束整个终端或所有同名 node/Electron。

从完整身份 B 切至仅浏览器身份 A：保护 B 的有效快照后，按现有白名单恢复 A；缺失 CLI/App 不保留 B 的活动登录。既有保留策略下的设置、历史、Skills/MCP 和项目资料保持原契约，不为清理登录状态扩大删除范围。

本地提交成功但 App/CLI 启动失败，应报告“资料已恢复、该端未启动”；不自动执行旧 CLI 工作，不自动启动未选端，不宣称云端登录状态可随本地事务回滚。B 继续使用独立目录，不复制整份浏览器资料入保险库、不重新随机化指纹。

## 6. 人工维护窗口与已检测冲突保护

范围覆盖当前用户、与当前/目标资料相关的 CLI 及后台进程、App 主进程/helper、B 主进程/helper。窗口关闭、主锁消失、PID 消失均不能单独代表全部退出。识别须包含真实路径、进程关系、精确资料参数和生命周期；含空格路径不按 shell 字符串猜拆，PID 同路径复用不能误当旧进程。

最少修补第 11 节三个已知缺口：macOS 生命周期复核；单候选查询失败向上报告未知；B 主锁之外的 helper/资料占用检查。查询失败不能被空列表吞掉，未知锁不自动删除，无关同名进程不结束。

**首版适用条件：用户在保存、切换、恢复操作期间保持相关 CLI/App/B 退出，不从 Dock、终端、自动重启器或其他入口启动、登录或修改资料；直到操作结束或明确待恢复。仅原地保存浏览器绑定、不读取其内容时，B 可沿用既有行为保持运行。** 不安装系统扩展，不取得系统级拦截权限。CCBaga 自己的写入与启动入口串行协调；快照前后、首次替换前、恢复/提交边界继续检查。发现进程或查询未知即中止，持久恢复保护保留。检查间完成的外部启动、写入、退出可能完全漏检，发生时不保证无串号/无数据覆盖。原失败反例继续可运行并明确演示此边界，不作为排他控制通过证据。

| 已检测到的外部重启/冲突阶段 | 必须保持的结果 |
| --- | --- |
| 尚未替换工作区（含快照期间） | 中止推进，不提交可疑快照、不覆盖最后有效代次，当前有效资料可恢复 |
| 恢复写入中、未完成提交 | 停止后续修改，保留恢复日志与有效快照，进入待恢复；活动进程退出前不继续恢复、不盲目回滚 |
| 已提交、尚未解除互斥 | 如实报告已提交状态及冲突，核对实际身份/完整性后按持久记录恢复，不反复自动切换 |
| 正常结束后再启动或手工登录 | 作为新状态更新；撤销过期身份/网络结论，不覆盖用户的新登录 |

轮询不等于系统级排他。D0 验收进程识别、正常静止路径、已观察冲突和持久恢复；D2 的真实客户端验收也须在人工维护窗口内完成。未经授权的外部并发写入不纳入一致性保证。恢复未完成时，CCBaga 重启后仍保留相关启动限制；界面必须在操作前展示维护窗口条件。

## 7. FlClash 最小只读接入

只接入用户授权准备的**本机回环、受认证**控制接口，读取生效配置、实际组选择与连接元数据；密钥留在原生受保护边界，不进入 UI 回执、命令行、日志或仓库。接口未开启/认证失败/进程匹配关闭分别报告原因。首版不内置 FlClash 偏好/源配置编辑器、不自动重载或修改节点/TUN/DNS；第 14–17 节的临时设置操作是现场验证方法，不变成默认后台操作。

基线最少记录实际网络、代理模式、规则/链与选择、DNS/IPv6 状态和客户端启动范围。用户确认的策略与当时观察值分开保存，不能把当前链抄成预期链。固定公网出口允许集合尚未确认，单列待确认，不妨碍展示“该请求经已确认代理链”的有限结果。

归属方法：客户端与配置/资料范围 → 当前生命周期与联网 helper → 源端口/系统套接字 → FlClash 连接 ID、目标类别、命中规则和完整代理链。processPath 可作为证据，但 App 已出现空字段，必须有系统侧补证路径；缺字段、补证失败、端口/PID 已复用或窗口错开时保持未知。

复用连接用同 ID 在观察窗口内的增量关联，不能只等新连接。网络页的独立探针仍作为辅助，不代替客户端请求。普通刷新/采样不自动发模型请求；用户显式触发实际操作后采集有界窗口，附时间、归属方式及范围。不做 TLS 解密，不收集认证头、请求正文或无关整机流量。

身份/进程、节点/规则、网络接口或相关 DNS 状态改变时，撤销受影响的旧结论并说明原因；系统自动 DNS 与手工设置分层比较。Wi-Fi 换网后重建基线，不把旧 IPv6 DNS 写回新网络。无请求、短连接遗漏、不可读取或未知不能沿用旧绿灯。

只展示已观察连接，不承诺完整旁路覆盖。公网固定出口、全部 DNS/IPv6/UDP、故障防直连均不在本次最小交付的通过声明中；检测异常不自动改网络或关闭程序。

源码的三个具体缺口：

1. **macOS 生命周期复核不足。** `cleaner.rs` 的 `signal_same_process` 比对 PID 与 executable；`ClaudeProcess.created` 仅 Windows 分支存在。macOS 的同路径 PID 复用风险尚未由创建时间等生命周期证据排除；这不是已经复现的误杀。
2. **部分查询失败会被略过。** `Cleanup.m` 枚举时对单进程 `proc_pidinfo`/`proc_pidpath` 失败使用 continue，CLI 参数读取失败返回不匹配；整个枚举成功不代表每个候选都被排除。新契约的“无法确认不得当作已退出”需要传播不确定性，不能直接复用空列表作为强保证。
3. **B 当前关闭判断依赖主锁。** `Browser.m` 的 `profileApplication` 通过 `SingletonLock` 找主进程，再检查当前用户、bundle ID 和 Chromium/CCBrowser 名称；`rf_browser_running` 没有独立枚举 helper。锁缺失、读取失败或主进程不匹配会返回未运行，尚不能证明剩余 helper 不持有资料；正常退出后的残留场景待实测。

定位：[CLI/进程识别及复核](../src-tauri/src/cleaner.rs)、[macOS Claude 进程枚举](../src-tauri/native/Cleanup.m)、[浏览器主锁判断](../src-tauri/native/Browser.m)、[浏览器等待退出](../src-tauri/src/browser/profile.rs)。本轮仅阅读源码，没有调用任何退出函数。

开始前确认目标账号/组织与预期代理链；账号仅在私有证据中记录必要标识，仓库使用端名/代号。当前选中节点不自动等同用户期望节点。若没有已确认的出口 IP/允许集合或固定出口证据，仍可验证请求路由，但出口正确性保持待确认，不能把当时测到的 IP 直接抄成期望值。

当前界面或原生登录状态与 CCBaga 档案是否保存该端凭证是两个问题，分列记录。未启动进程不代表没有凭证；浏览器已保存也不代表 App/CLI 已登录。以下为执行前方案，实际状态见第 16 节。

### 15.2 最小执行顺序

1. **固定基线并开启短时观察。** 备份第 14 节的新状态，受控启用本机认证接口和 always 进程匹配；保留 DNS 覆写关闭、TUN 关闭、原节点/规则/系统代理。确认认证、运行时配置、实际代理组选择与基线一致后，才进行客户端操作。记录现有进程生命周期、资料目录、helper、相关套接字；只保留脱敏关联结果，不导出完整参数/环境或凭证。
2. **逐端核对身份并产生一个业务样本。** 顺序为 B → App → CLI，每次只主动操作一个端；已有其他程序无需退出。先核对当前实际账号/组织及登录是否可用，再在全新空会话发送“网络验证，请只回复 OK”，不附文件、不引用旧聊天、不进入业务项目。默认每端一次主动提交，最多三次；客户端内部重试如发生须记录，不把失败变成持续循环。授权未含重试时，不再次主动发送。
3. **关联业务动作与真实连接。** 采集从动作前开始，到响应或明确失败结束的短时连续连接快照及相关系统套接字。对复用连接同时记录同一 connection ID 的流量增量，而不是只找新连接；结合时间、目标、端/资料/进程、客户端完成回执建立对应。仅凭“同一时间有 claude 域名流量”不足以归属。如果后台请求使证据有歧义，则记未核验；不靠更频繁轮询假装解决短连接遗漏。
4. **分端判定并清理。** 输出三端结果表和证据覆盖边界，恢复接口、进程匹配及临时自动更新暂停，保留 DNS/TUN 关闭，复核源配置、运行态、节点选择和系统状态。默认保留用户既有窗口、会话和登录；仅清理获授权创建的临时观察资料，不删除聊天、退出账号或自动保存覆盖 CCBaga 档案。

建议为每端设一个有限观察窗口（执行参数提案：动作前约 5 秒，响应结束后约 5 秒，单端最长 60 秒），只用于控制采样和成本，不是“超过 60 秒即网络不合格”的业务限制。超时记录实际阶段；停止观测不等于强制终止既有进程。若需要延长、再次请求或重启客户端，应依据已有授权范围处理，范围外先明确追加操作。

| 端 | 最小实际操作 | 必须核对的归属与覆盖 |
| --- | --- | --- |
| CCBaga-B | 在当前受管资料中新开 Claude 标签页；已登录时新建空聊天并发一次测试文本 | 主进程、user-data-dir、NetworkService/helper、源端口、实际连接和规则/代理链；普通 Chrome/Safari 的成功不代替 B |

### 15.5 验收标准与判定

每端证据记录：客户端版本及启动方式、脱敏账号/组织确认来源、资料/配置范围、动作开始结束时间、响应状态、进程/生命周期/helper 归属、关联方法、连接 ID/协议/目标类别、命中规则/完整代理链、观察到的直接连接及未知项。仓库只记结论与必要摘要；细粒度元数据留在私有有时限的验证目录。

| 验收项 | 通过条件 | 未通过或未核验条件 |
| --- | --- | --- |
| 单端业务请求与身份 | 目标账号/组织核对明确；该端一次真实受认证请求取得响应 | 登录页、缓存页面、版本/状态命令不算；缺登录/无权益/身份不符分别记录 |
| 进程与连接归属 | 可将该端及其资料/helper 与测试时段连接可靠对应；路径/套接字/生命周期证据互相支持 | 缺路径且系统侧无法补足、PID 归属不明、短连接遗漏、混入其他客户端或仅时间相关时标未核验 |
| 请求路由符合预期 | 对已归属的 Claude 业务连接取得规则和完整链，最终出口节点/策略符合事前确认；三端结果分别具备证据 | 未授权的 DIRECT/其他链判不符合；只有配置、节点名称或独立 curl 结果不能判通过 |
| 系统侧观察与结论边界 | 对测试窗口内相关进程的可观察连接做交叉核对，区分本地通信、代理隧道、允许的引导通信与 Claude 直连；记录 IPv4/IPv6、TCP/UDP/DNS 哪些有证据 | 没在 FlClash 列表看到异常不能证明无旁路；系统解析进程/加密 DNS 无法归属时明确缺口，不给无泄漏结论 |
| 恢复与不破坏既有使用 | 临时接口/进程匹配/自动更新暂停恢复；DNS/TUN 仍关闭、节点和系统设置不变；既有三端工作与凭证未被擅自关闭/覆盖 | 只恢复文件而未复核运行态/选择不算完成；不以删资料、改节点或断掉全部网络换取通过 |

首轮只有三端分别满足身份、业务响应、可靠归属和预期路由，才可写“本次三端已验证请求的路由一致”。有一端缺登录或证据不足则只报告已验证的子集，整体验证未完成；服务错误、登录错误、超时与错误路由分开判定，不能把一切失败统称为网络不符合。

即使首轮路由通过，也不自动通过“固定公网出口一致”“全部 DNS 无旁路”或“故障期间不直连”：固定出口需要独立的已确认出口基线及辅助实测，并保留服务端实际所见 IP 的不可见边界；DNS/IPv6/UDP 与故障保护按第 7、9 节另做专项。若发现流量明确绕过预期代理，先报告该端实际路径和最小修正提案，不自动启用 TUN、改节点或开发功能。
